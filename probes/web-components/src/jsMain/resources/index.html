1. The published example (override val connectedCallback)

Renders “MyPanel test content!” — but connectedCallback never runs, so “MyPanel connected!” is missing from the console.

2. The same, with @JsName("connectedCallback") fun

This one is called and then throws RangeError: Maximum call stack size exceeded on its first DOM access.

3. Empty external superclass + unsafeCast to HTMLElement

Creates, connects, queries the DOM and injects content — no stack overflow, because the superclass declares no DOM members for Kotlin to re-emit.

4. Bridge superclass + the official CustomElement interface

Same bridge, but the lifecycle hook is the interface's `override val connectedCallback`. Watch whether “MyPanelIf connected!” appears.

5. Bridge superclass carrying the official interfaces

Same as 3, but `querySelectorAll` / `setAttribute` / `innerHTML` are called on `this` with no cast.

6. Interface bundle without Element

Empty superclass + `ElementCSSInlineStyle`/`ElementContentEditable`/`GlobalEventHandlers`/ `HTMLOrSVGOrMathMLElement`. Reads `style` through the interface, the rest through `html`.

7. Official HTMLElement spelling through a super-forwarding adapter

All DOM calls go through `…Super` methods (or an overridable `remove()`); no JS bridge.
